# NiK Smart Count — نرم‌افزار حسابداری و مدیریت مالی ساختمانی

سیستم یکپارچهٔ حسابداری، بودجه و کنترل مصارف شرکت‌های ساختمانی — فارسی/دری، پشتو و انگلیسی،
با پشتیبانی چندشرکتی (multi-tenant)، ورود مدیر ارشد (دفتر هفت) و کارمندان شرکت.

نسخهٔ استقرار: هر فایل همین ریشه روی هاست PHP/MySQL (cPanel) کپی می‌شود.

---

## ۱. معماری در یک نگاه

```
login.php / office7-login.php     صفحهٔ ورود کارمند و مدیر ارشد
workspace.php                     پوستهٔ اپلیکیشن (SPA) — کل منطق در باندل است
office7.php                       پنل مدیر ارشد (دفتر هفت)
team.php                          مدیریت کارمندان شرکت
  │
  ├── nsc-runtime.php             سرو باندل فشردهٔ کلاینت + ETag/304
  └── api/*.php                   REST API (JSON)
        ├── config.php            تنظیمات، هدرهای امنیتی، گارد CSRF/Origin
        ├── db.php                اتصال PDO، JWT، مجوزها، ارتقای خودکار ساختار
        ├── auth.php              ورود، ساخت/همگام‌سازی کاربر، ابطال نشست
        └── …                     finance, materials, payroll, reports, files …
              │
              └── MySQL 8 / MariaDB 10.3+
                    ساختار مرجع: api/.secrets/schema.sql
```

سه لایهٔ اعتماد:
1. **کاربر** — توکن HMAC-SHA256 امضاشده، ۳۰ روزه، با `token_version` برای ابطال فوری.
2. **شرکت (tenant)** — `currentTenantId()` در هر اندپوینت؛ هیچ کوئری بدون فیلتر شرکت نیست.
3. **پروژه** — `assertTenantProjectAccess()` پیش از هر نوشتن/خواندن پروژه‌ای.

## ۳. نصب (خلاصه)

مسیر کامل: [`docs/DEPLOY.md`](docs/DEPLOY.md)

```bash
# ۱) همهٔ فایل‌ها را در public_html کپی کنید (نه در زیرپوشه، چون مسیرها مطلق‌اند)
# ۲) کلید نصب را بسازید (یا در cPanel File Manager یک فایل متنی ۴۸ کاراکتری بسازید)
php tools/nsc-init.php

# ۳) مرورگر: /installer.php
#    الف) کلید نصب + مشخصات دیتابیس → «آزمایش اتصال» → «ذخیرهٔ اتصال»
#    ب) ساخت مدیر اصلی → «تکمیل نصب»
```

پس از تکمیل، `api/.secrets/installed.lock` ساخته می‌شود و نصب دوباره مسدود می‌گردد.

## ۴. ارتقا و ساختار دیتابیس

- منبع واحد: `api/.secrets/schema.sql` — همهٔ دستورها `CREATE TABLE IF NOT EXISTS` و
  `INSERT IGNORE` هستند، یعنی **هیچ ردیفی حذف یا بازنویسی نمی‌شود**.
- نسخهٔ ساختار در `api/db.php` (`NSC_SCHEMA_VERSION`) و در جدول `nsc_schema_meta` ثبت می‌شود.
  اگر این دو ناهمخوان باشند، **در اولین درخواست API** ساختار خودکار ارتقا می‌یابد
  (`nscSchemaEnsure`)، پس دیگر لازم نیست منتظر اجرای دستی مهاجرت بمانید.
- ارتقای دستی (برای مدیر ارشد): `POST /api/admin.php?action=upgrade`
- بازبینی سلامت و ساختار: `GET /api/health.php` — جدول‌های غایب و نسخهٔ ساختار را گزارش می‌کند
  و هیچ اطلاعات حساسی (رمز، نام دیتابیس، کاربر) برنمی‌گرداند.

> اگر یوزر دیتابیس دسترسی `CREATE`/`ALTER` نداشته باشد، ارتقای خودکار در لاگ خطا ثبت می‌شود و
> هر ساعت یک‌بار تلاش می‌کند (نه در هر درخواست). در این حالت دسترسی‌ها را در cPanel اصلاح کنید.

## ۵. نگهداری و پشتیبان‌گیری

| کار | مسیر |
|---|---|
| پشتیبان دیتابیس | `mysqldump` از cPanel، یا بکاپ JSON از داخل برنامه |
| بازگردانی | ایمپورت SQL + کپی مجدد `uploads/` |
| چرخش کلید امضا | حذف `api/.secrets/jwt_secret.key` → کلید تازه ساخته می‌شود و همهٔ نشست‌ها باطل می‌شوند |
| ابطال نشست یک کاربر | پنل دفتر هفت → «خروج از همه دستگاه‌ها» (`auth.php?action=logout_all`) |
| بازبینی سرور | `php tools/nsc-init.php --check` |

**هرگز** این فایل‌ها را در گیت نگذارید: `api/.secrets/database.php`، `jwt_secret.key`،
`install.key`، `installed.lock`. فهرست کامل در [`.gitignore`](.gitignore) است و
`api/.htaccess` دسترسی وب به آن‌ها را هم می‌بندد.

## ۶. شکستن مشکلات رایج

| نشانه | علت محتمل | کار |
|---|---|---|
| صفحهٔ سفید / ۵۰۰ در روزنامچه | ساختار قدیمی (جدول‌های غایب) | یک‌بار `GET /api/health.php` → ارتقای خودکار |
| «افزونه pdo_mysql فعال نیست» | PHP هاست | فعال‌سازی از cPanel → Select PHP Version |
| «کلید نصب نامعتبر است» | `install.key` نیست یا فرق دارد | `php tools/nsc-init.php` |
| «برای ساخت مدیر، سایت را با HTTPS باز کنید» | مرورگر بدون HTTPS | SSL را فعال کنید |
| کاربر پس از آپدیت نسخهٔ قدیمی می‌بیند | کش باندل | اکنون با ETag حل شده؛ `Ctrl+F5` یک‌بار |
| «نسخهٔ سرور تغییر کرده است» در ذخیره | همگام‌سازی هم‌زمان دو دستگاه | صفحه را تازه کنید؛ تعارض‌ها ادغام می‌شوند |

## ۷. وضعیت فعلی کد (صادقانه)

**پیاده‌شده و آزموده‌شده در بازبینی استاتیک:** احراز هویت و RBAC، جداسازی شرکت/پروژه،
گارد CSRF، محدودیت تلاش ورود، سخت‌سازی آپلود، قفل نصب، ارتقای خودکار ساختار،
درخت حساب‌های استاندارد (۱۸۶ حساب، هم‌کد با کلاینت).

**محدودیت‌های شناخته‌شده:**
- گزارش‌های رابطه‌ای (`reports.php`, `finance.php`) از جدول‌های SQL می‌خوانند، در حالی که
  نوشتن اصلی کلاینت در فضای کاری JSON (`workspace_sync_states`) انجام می‌شود. تا زمانی که
  یک «پروجکتور» از JSON به جدول‌های رابطه‌ای ساخته نشود، این گزارش‌ها برای داده‌های
  وارد‌شده از UI خالی می‌مانند. این تنها شکاف معماری باقی‌مانده است.
- مسیر ذخیره‌سازی رسمی، `api/workspace.php` است (جدول `app_workspaces`): صفحهٔ
  `workspace.php` با `window.NSC_PERSIST` آن را صدا می‌زند و کنترل تعارض بر پایهٔ نسخه
  (`baseVersion` → 409) انجام می‌شود. اکشن `office7.php?action=workspace_sync` برای
  سازگاری مانده و فراخواننده‌ای در کلاینت ندارد.
- `api/files.php` (مدیریت فایل) در کلاینت فعلی به UI وصل نشده است.
