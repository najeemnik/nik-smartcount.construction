# راهنمای استقرار NiK Smart Count روی هاست cPanel

این سند مراحل کامل نصب، ارتقا و بازگردانی را روی یک هاست اشتراکی (Apache + PHP + MySQL) توضیح می‌دهد.
زمان تخمینی: ۱۵–۲۰ دقیقه برای نصب تازه.

---

## ۰. چک‌لیست پیش از شروع

- [ ] دامنه با SSL فعال (HTTPS) — بدون آن، ساخت رمز مدیر در مرورگر کار نمی‌کند.
- [ ] دسترسی به cPanel → **MySQL Databases** و **File Manager**.
- [ ] نسخهٔ PHP هاست ۷.۴ یا بالاتر.
- [ ] فایل‌های پروژه: کل پوشهٔ مخزن (بدون `node_modules` و بدون `review/`).

---

## ۱. ساخت دیتابیس

1. cPanel → **MySQL® Databases**
2. **Create New Database** → مثلاً `nsc` → نام نهایی می‌شود `user_nsc` (پیشوند حساب هاست را یادداشت کنید).
3. **Add New User** → یوزر و رمز قوی → رمز را نگه دارید.
4. **Add User To Database** → کاربر را به دیتابیس اضافه کنید → **ALL PRIVILEGES**.

> ارتقای خودکار ساختار به دسترسی `CREATE`/`ALTER` نیاز دارد؛ **ALL PRIVILEGES** لازم است.

---

## ۲. آپلود فایل‌ها

1. cPanel → **File Manager** → `public_html`
2. آپلود فایل‌های پروژه. **مهم:** مسیرها مطلق‌اند (`/api/`, `/assets/`)، پس پروژه باید
   در ریشهٔ دامنه باشد، نه در زیرپوشه.
3. مطمئن شوید این فایل‌ها آپلود شده‌اند (فایل‌های مخفی معمولاً جا می‌مانند):
   `.htaccess`، `api/.htaccess`، `api/.secrets/.htaccess`، `uploads/.htaccess`، `manifest.webmanifest`

**دسترسی پوشه‌ها** (از File Manager → Permissions):

| مسیر | دسترسی |
|---|---|
| `api/.secrets/` | `700` |
| `uploads/` | `755` (یا `775` اگر PHP با مالک دیگری اجرا می‌شود) |
| فایل‌های `*.php` | `644` |

---

## ۳. ساخت کلید نصب

نصب بدون کلید انجام نمی‌شود (تا هیچ‌کس نتواند نصب را برباید). دو راه:

**راه الف — خط فرمان (پیشنهادی):**

```bash
cd ~/public_html
php tools/nsc-init.php
```

خروجی یک کلید ۴۸ کاراکتری چاپ می‌کند و آن را در `api/.secrets/install.key` با دسترسی `0600` می‌نویسد.

**راه ب — بدون SSH (File Manager):**

1. یک فایل متنی بسازید، یک رشتهٔ تصادفی ۴۸ کاراکتری (فقط `a-z0-9`) داخلش بگذارید.
2. آن را با نام `install.key` در `api/.secrets/` ذخیره کنید.
3. دسترسی فایل را `600` کنید.

---

## ۴. نصب از مرورگر

به `https://دامنه/installer.php` بروید و دو مرحله را کامل کنید:

### مرحلهٔ ۱ — اتصال دیتابیس
| فیلد | مقدار |
|---|---|
| کلید نصب | همان کلیدی که ساختید |
| سرور دیتابیس | `localhost` |
| پورت | `3306` |
| نام دیتابیس | نام کامل با پیشوند، مثل `user_nsc` |
| یوزر دیتابیس | نام کامل، مثل `user_nscadmin` |
| رمز | رمز همان یوزر |

«آزمایش اتصال» → پیام سبز → «ذخیرهٔ اتصال».  
این مرحله `api/.secrets/database.php` را می‌نویسد و از نسخهٔ قبلی (اگر باشد) پشتیبان می‌گیرد.

### مرحلهٔ ۲ — مدیر اصلی
نام، نام کاربری، شرکت و رمز (حداقل ۱۲ حرف) را وارد کنید. رمز در مرورگر هش می‌شود و
سرور آن را با Bcrypt ذخیره می‌کند؛ **رمز خام هرگز ذخیره نمی‌شود**.

پس از موفقیت:
- `api/.secrets/installed.lock` ساخته می‌شود (نصب دوباره مسدود).
- کل ساختار ۳۴ جدول + دفتر حساب‌های استاندارد (۱۸۶ حساب) ساخته می‌شود.

---

## ۵. ورود

| نقش | آدرس |
|---|---|
| مدیر شرکت / کارمند | `https://دامنه/login.php` |
| مدیر ارشد (دفتر هفت) | `https://دامنه/office7-login.php` |

## ۶. پس از نصب — بازبینی سلامت

```bash
curl -s https://دامنه/api/health.php
```

پاسخ باید شامل این‌ها باشد:

```json
{
  "ok": true,
  "configured": true,
  "initialized": true,
  "connected": true,
  "schemaUpToDate": true,
  "missingTables": [],
  "checks": { "secretsWritable": true, "uploadsWritable": true, "https": true }
}
```

اگر `ok: false` بود، `missingTables` و `checks` دقیقاً می‌گویند چه چیزی کم است.

---

## ۷. ارتقا (نسخهٔ جدید روی نصب موجود)

1. **اول بکاپ:** cPanel → phpMyAdmin → Export (SQL) + آرشیو پوشهٔ `uploads/`.
2. فایل‌های جدید را روی همان مسیرها جای‌گزین کنید.
3. `api/.secrets/database.php`، `jwt_secret.key` و `uploads/` را **دست نزنید**.
4. اولین بار که صفحه باز شود، ساختار خودکار ارتقا می‌یابد (چون `NSC_SCHEMA_VERSION` عوض شده است).
5. بازبینی: `GET /api/health.php` → باید `schemaUpToDate: true` بدهد.

ارتقا هرگز جدولی را حذف یا ردیفی را بازنویسی نمی‌کند؛ همهٔ دستورها `IF NOT EXISTS` / `INSERT IGNORE` هستند.
اگر می‌خواهید قبل از ترافیک واقعی اجرا شود: `POST /api/admin.php?action=upgrade` با توکن مدیر ارشد.

---

## ۸. بازگردانی از بکاپ

1. فایل‌های کد را در جای خود بگذارید.
2. `install.key` را بازسازی کنید (`php tools/nsc-init.php`).
3. `api/.secrets/installed.lock` را **حذف نکنید** — وجودش مانع نصب دوباره است، ولی جلوی
   بازگردانی دیتابیس را نمی‌گیرد.
4. دیتابیس را از SQL ایمپورت کنید و `uploads/` را برگردانید.
5. اگر `database.php` را هم از دست داده‌اید، `/installer.php` را با همان مشخصات دیتابیس
   دوباره پر کنید (چون `installed.lock` هست، فقط مرحلهٔ اتصال را نمی‌پذیرد؛ در این حالت
   `database.php` را از بکاپ خودتان برگردانید).

## ۹. خطاهای رایج

| پیام | معنا | راه‌حل |
|---|---|---|
| `[NSC-DB-1045]` | یوزر/رمز MySQL غلط | نام کامل یوزر را از cPanel کپی کنید |
| `[NSC-DB-1044]` | یوزر به دیتابیس دسترسی ندارد | Add User To Database → ALL PRIVILEGES |
| `[NSC-DB-1049]` | نام دیتابیس پیدا نشد | پیشوند حساب هاست را فراموش نکنید |
| `[NSC-DRIVER]` | `pdo_mysql` فعال نیست | cPanel → Select PHP Version → Extensions |
| «کلید نصب نامعتبر است» | `install.key` نیست/فرق دارد | `php tools/nsc-init.php` |
| «نصب قبلاً قفل شده است» | `installed.lock` موجود است | طبیعی است؛ از `login.php` وارد شوید |
| «برای ساخت مدیر، سایت را با HTTPS باز کنید» | `crypto.subtle` نیاز به HTTPS دارد | SSL را فعال کنید |
| صفحهٔ سفید بدون پیام | خطای PHP پنهان است | `error_log` هاست را ببینید (نمایش خطا عمداً خاموش است) |

---

## ۱۰. امنیت — چیزهایی که نباید تغییر کنند

- `api/.secrets/` هرگز در `public_html` در دسترس وب نباشد (`.htaccess` موجود است؛ حذفش نکنید).
- `display_errors` باید `0` بماند (در `api/config.php` تنظیم شده).
- `uploads/` نباید اجازهٔ اجرای PHP بدهد (`.htaccess` آن را با `php_flag engine off` می‌بندد).
- بکاپ `api/.secrets/database.php` را بیرون از `public_html` نگه دارید.

## ۱۱. نگهداری دوره‌ای

| هر | کار |
|---|---|
| روزانه | بکاپ خودکار MySQL (cron هاست یا سرویس بکاپ) |
| هفتگی | آرشیو `uploads/` |
| ماهانه | `php tools/nsc-init.php --check` و بازبینی `api/system_audit_logs` از پنل دفتر هفت |
| پس از هر حادثه | چرخش کلید امضا (حذف `jwt_secret.key`) + «خروج از همه دستگاه‌ها» برای کاربران مشکوک |
